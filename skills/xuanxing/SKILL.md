# 性价比选型（xuanxing）

把用户给的一条任务提示词，改写成按环节分配不同模型的分段提示词，追求最高性价比。

## 触发

用户说「选型」「性价比」「配模型」「优化提示词并选模型」，或丢来一条要动手的开发/创作类大任务并希望按性价比分配模型时使用。

## 流程（4 步）

1. **解码分叉**：一句话复述任务，找出会改变提示词架构的关键分叉（如：联机/同屏、部署目标、内容尺度由谁写、单文件还是多模块），一轮 ≤3 问，每问带默认值。用户回「对」或给出选项后立即进入执行，不再二次确认。
2. **刷新数据**（每次运行都刷，不读旧数字凑合）：用你自己信得过的模型榜单与价格来源（官方定价页、公开排行榜、或自建的价格监控表），算「性价比指数＝场景共识指数 ÷ 场景混合价 ×100」。没有现成数据源时先问用户要价格表或榜单链接，不凭记忆报数。

3. **分段与选型**（口径已锁定，不改）：
   - 性价比指数 = 场景共识指数 ÷ 场景混合价 ×100，只在同一场景内可比。以指数为主，但设质量地板：场景分明显偏低的高指数模型是「伪第一」，要避开（如编程榜低分高指数的 Flash 档，返工一次亏掉全部差价）。
   - 不限于各榜前三。每环节在对应场景榜里找「够用的最低价」：设计/文案→专业榜，写码→编程榜，逻辑/规则/审查→推理榜，查资料→知识榜。兜底保险段按指数选平价高分模型（分数最高但指数减半的不选）。
   - 默认分段骨架：设计 / 内容 / 实现 / 审查 / 兜底，按任务类型增删。每段提示词必须含：角色设定、上下文粘贴位（标明粘上一段哪个产物）、硬性约束、验收清单、输出格式（长文件类约定分批输出规则）。
   - 涉成人/敏感内容时：尺度分档与模型宽容度对应——显式重档优先 xAI、DeepSeek 系，轻档可用低价国产档；Google、Anthropic 系只接非显式环节。唯一默认保留的红线是物理安全线（非尺度线），并在文档里注明红线段可自行增删。
   - 成本预估：按各段假设 token 量 × 当日混合价列表，给常规合计、含兜底合计、¥ 封顶建议三行；算式写明可复核。
4. **交付**：输出 md，命名「<任务名>-分段提示词与选型.md」，结构＝选型总表 / 为什么不用更贵的 / 成本预估（常规合计、含兜底合计、建议封顶）。

## 注意

- 模型分数与价格一律以当日 报告.md 为准，不凭记忆报数；引用的每个数字要能在报告里对上。
- 选型理由必须写出来（为什么不用某榜指数第一），这是文档的核心价值，不是装饰。
- 只产出交付文件与数据快照，不动用户的其他文件。
