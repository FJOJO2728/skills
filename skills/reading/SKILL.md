# reading · 一本书 → 一页可读的 HTML

核心交付两条线：**书 → HTML 读书页**（主线，一至四节）；**英文学术文献 → 对照翻译**（第六节，说「学术翻译」时走）。成品通用，不带个人工作痕迹与路径。

## 一、输入与产出

**输入**：一本书（epub／pdf／mobi／txt／md 均可；pdf 用 `python3 -m markitdown` 提文本）＋用户口味（可选：强调什么、给谁读、风格）。

**产出（缺一不可）**：

1. **书名页**：书名、作者、译者（如有）、一句话荐语（读完全书后写）、预计阅读时长。
2. **「怎么读这本书」**：主线一句话＋速读、细读两种读法（各看哪几章）。**不代拟「挑读」路径**——按兴趣挑读是读者自己的事。
3. **全局导航**：侧栏章节目录（可折叠章-节树）、顶栏搜索框、阅读进度条。
4. **正文（全面细致）**：章节**全覆盖不节选**——每章开头一段「本章说什么」（3-5 句导读，可附关键概念词条卡），随后是该章全文（忠实原文，不改写不缩写）；难词、典故、概念随手脚注；书末附关键词索引。**原书的章号章题不得在正文重复出现**——章头只保留页面自己的章标题组件，正文里原样重复的「CHAPTER N／章题」段落一律剔除（挂在其上的脚注回链改指章首）。
5. **注释双向跳转**：正文脚注引用↔章末原注，双向可跳（引用→注、注→引用）；正文侧引用带稳定 id，注侧挂「↩」返回链。
6. **可视化（至少三件）**：**人物关系图**（节点=人物，连线=关系并标关系词）；**时间线**（主线事件按序排布）；**概念图谱或结构图**（概念间的包含、对立、递进）；有数据就加对比条形／占比图。图一律画在页面里（SVG／CSS），不贴截图。
7. **可交互（至少五件）**：目录点击跳转、全文搜索高亮定位、字号切换、日/夜主题切换、阅读进度记忆（localStorage）、章节折叠、注释双向跳转。金句页与收藏**默认不做**——金句取舍因人而异，用户点名要才加。

## 二、做法（按序）

1. **取全文**：把书转成纯文本，落一份 md 到工作层（同目录 `书名_全文.md`），后面一切以它为准。脚注集中存放的书，逐章抽回并按「编号段开新注、无编号段并入前注」归组，防止注序错位。
2. **通读提结构**：列出章节树、主线脉络、人物表、概念表、时间线事件、金句候选。**先建结构表再写页面**——结构错，整页白做。
3. **写导读**：每章 3-5 句「本章说什么」；全书开头一页「怎么读这本书」（主线一句话＋速读／细读两种读法）。
4. **画图**：按可视化清单画 SVG，布局舒展、中文标签、手机可看。
5. **组装单文件 HTML**：CSS/JS 全部内联、零外部请求；衬线正文（Noto Serif SC／思源宋体，西文 Georgia 类）；纸感底色、章间留白；手机优先适配。建议「母本模板＋构建脚本」分工：内容数据（导读/词条/图）进脚本，外壳与交互进模板，重跑脚本即重建。
6. **双主题逐项过对比度**：日/夜主题不是简单反转变量——深色装饰区（如封面 hero）**两套主题下都固定深色**，导航、按钮、占位符、辅助文字等所有固定配色在日间主题下逐一核对，弱金（#C9A227 系）在浅底上一律换深金（#8a711c 系）或墨色。
7. **自检**：对照下面验收逐条过关再交付。

## 三、验收（交付前逐条看）

- 章节无遗漏：目录条目数＝正文实际章节数。
- 导读每章有、图≥3、交互≥5；正文无重复章题段。
- 注释双向跳转可用：点引用到注、点「↩」回正文；无死链。
- 日间主题下读一遍：正文、导航、按钮、页脚、占位符全部清晰可读。
- 搜索能搜到并跳准；刷新后进度还在；手机宽度不横向滚动。
- 内容忠于原著：引文、人名、年代核对无误；补充的解释用「注」样式区分，不混进原文。核对引文人名时注意剔除脚注标记与排版归一（编号后补空格之类）再比对，避免假报警。
- 单文件、无外链、断网可开。

## 四、分寸

知识正确 ＞ 完整 ＞ 好读 ＞ 交互 ＞ 装饰。图是为看懂关系，不为炫技；页面宁可朴素，不加无关动效。读法路径（速读/细读之外的挑读）与金句取舍交还给读者。长文本（全文 md、结构表）进工作层由 Agent 维护，用户只看 HTML。

## 五、附带：导读与读书笔记（旧线保留）

说「导读某书／文献」而没要 HTML 时，出 md 导读：速通导读 → 按目录逐级导读（每级给代表性原文段＋中译对照）→ 高级谈资（深层观点／对照阅读，区分「文本依据／合理推断／延伸解读」，严禁虚构出处）。

说「阅读笔记／读书笔记处理」时，按三部曲出 md：**收获**（科普谈资式讲清）→ **疑惑**（批注细说）→ **共鸣**（荐新文献）。

两者可并行：先出读书页，再按需补 md 笔记。


## 六、学术文献翻译（第二模式）

英文文献（期刊论文、书籍章节等）说「学术翻译」时走这条线：产出一份 md，按序五步，各步之间用 `---` 分隔。

1. **CMS 18 引用**：读 PDF 前几页取书目信息（作者全名、标题、期刊名含副标题、卷期、年份、页码、DOI），按《芝加哥手册》第 18 版给全场景样本——注释-参考文献体系（首引／带页码／简化／Ibid. 同页与异页／参考文献条目）＋作者-日期体系（基本／单页／范围／作者已在句中／文献列表）＋特殊场景（带 DOI／无 DOI 在线文献含访问日期／同年多篇 2021a、2021b）。代码块包裹，只给格式样本，不展开解释。
2. **摘要·关键词·目录双语对照**：标题、作者（姓名·机构·ORCID）、摘要（英中逐段对照、完整不缩写）、关键词（逐条并列）、目录（各级标题嵌套，`**I. English Title · 中文标题**`，子标题缩进）。英中之间用 `·` 或 `|` 分隔，不反复标注「原文／译文」，粗体标层级。
3. **确认翻译范围**：动手前必须先问——①全文（Introduction→Conclusion，不含 References/Notes，默认推荐）②指定章节（按第 2 步真实目录列选项，不编造不存在的章节）③自定义。等用户明确回复才继续；未回应或说「随便」按全文。
4. **书评（全网搜罗＋对原文核验）**：用 WebSearch 以标题／作者／期刊为核心词，中英及原语种多轮检索（＋review／书评／访谈等）；渠道不限——期刊书评栏、出版社与作者官网、豆瓣/Goodreads、学术博客、课程引用、社媒讨论；长短、褒贬、各立场一律纳入，关键来源用 WebFetch 细读，取不到就如实说明、不强抓。写作：每个观点与原文对照核验，网评与原文不符以原文为准并指出出入；框架＝概况与作者背景→结构与主要论点→学术贡献→各方评价（标来源、褒贬并存）→局限与争议→独立评判。书评针对全文，不因翻译范围裁剪；材料不足如实说明检索情况，不编造来源。
5. **逐段对照翻译**：按第 3 步范围。每小节标题后用引用块给 `> **导读：**` 一两句（点主题、在论证中的位置、需留意的概念；只铺垫语境，不展开解读、不剧透结论）；标题双语 `### English Title · 中文标题`；正文英文一段、中文一段，段落间 `---`；**可读性优先**——准确前提下允许调整句式、拆分长句、必要时意译；专名／术语首现时中文译名后括注原文；脚注尾注一并翻（原注一行、译文一行，编号与正文引用一致）；引文保留英文原样，中文译文以「」紧随；书名／期刊名译名后括注原文并用斜体标原文。

   脚注格式示例：
   ```
   ¹⁴ Sonya S. Lee, *Surviving Nirvana: Death of the Buddha in Chinese Visual Culture* (Hong Kong: Hong Kong University Press, 2010), 199.
   ¹⁴ 李索尼娅，《涅槃续存：中国视觉文化中的佛陀之死》（香港：香港大学出版社，2010年），第199页。
   ```

**细则**：PDF 文字提取不可靠时用 `pdftotext` 命令行兜底；各级标题读全文后归纳，不编造；输出 Markdown、不额外生成文件（用户要求除外）；书评必须实际调用检索工具，不得凭既有知识撰写，外部评价须标来源；翻译范围以用户确认为准，执行中不自行变更。
